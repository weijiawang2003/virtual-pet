# Phase 13: i18n infrastructure

**Goal**: Hand-rolled pure-TS i18n. Small enough that adding i18next would be
overkill; large enough that scattered string literals would rot.

**Dependencies**: none (depends on Phase 11 only for StringKey references that
link to visual keys — kept minimal).

## Deliverables

1. `src/core/i18n/types.ts` — `Locale` union + `DEFAULT_LOCALE`.
2. `src/core/i18n/keys.ts` — `StringKey` union covering ~50 system strings:
   screen titles, action buttons, permission-request descriptions, settings
   labels, notification templates, stage labels, mood labels, stat labels,
   and common UI verbs.
3. `src/core/i18n/translations.ts` — `TRANSLATIONS: Record<Locale,
Record<StringKey, string>>`. Both `zh-CN` and `en-US` fully populated.
   (File may exceed 300-line cap per scope — CLAUDE.md §6 limit waived for
   centralized translation tables.)
4. `src/core/i18n/t.ts` — `t(key, locale, vars?): string` with `{{name}}`
   interpolation. Unknown keys return the key itself and call `console.warn`.
5. `src/core/i18n/__tests__/completeness.test.ts` — every locale has every key.
6. `src/core/i18n/t.test.ts` — t() behavior: hits, missing keys, interpolation.

## Scope decisions

- **Locale shape**: just `'zh-CN' | 'en-US'` for now. Adding a third is a
  copy-and-translate exercise, not an architecture change.
- **No ICU plural / gender**: keep the interpolator dumb. If plurals ever
  matter we'll add i18next behind an ADR.
- **`console.warn` is allowed** by our ESLint config for fallback logging;
  CLAUDE.md §8 only prohibits `console.log`.
- **StringKey naming**: `noun.noun` or `noun.noun.detail` hierarchy, dot-separated,
  lowercase. Keeps alphabetical ordering in translation files coherent.
- **Templates stay simple**: `{{name}}` interpolation. Untouched if var is
  missing (template literal remains as-is — caller issue, not ours).

## Invariants (tested)

1. Every `StringKey` has a translation in every `Locale`.
2. `t(missing-key, locale)` returns the key string (warn side effect) — caller
   still gets a stable string for UI rendering.
3. `t(key, locale, { name: 'X' })` replaces `{{name}}` with `'X'` everywhere
   in the template.
4. Missing vars leave the template placeholder intact.
